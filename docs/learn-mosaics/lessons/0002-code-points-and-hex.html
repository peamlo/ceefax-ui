A character is a number

Hex: counting in sixteens

U+ means “a code point, written in hexadecimal”. Hex has sixteen digits instead of ten:

hex0–9ABCDEF
value0–9101112131415

In a two-digit hex number the left digit counts sixteens and the right one counts ones, the way decimal counts tens and ones. So 0x13 = 1 × 16 + 3 = 19, and 0x2D = 2 × 16 + 13 = 45. 0x is how JavaScript and CSS mark a hex number; U+ is how Unicode does. Same digits underneath.

Converting by hand

Hex → decimal: multiply and add. Each place is worth 16 times the place to its right (1, 16, 256, 4096, …). Turn letters into their values, multiply each digit by its place, add:

  1. 0x2D: D is 13
  2. 2 × 16 + 13 × 1
  3. 32 + 13 = 45

Decimal → hex: divide by 16. The quotient is the left digit, the remainder the right one (turn 10–15 into A–F):

  1. 45 ÷ 16 = 2, remainder 13
  2. 13 is D
  3. so 45 = 0x2D

That covers 0–255, every two-digit hex number, which is all the mosaic offsets need. For bigger numbers keep going: 0x258C (▌) = 2 × 4096 + 5 × 256 + 8 × 16 + 12 = 9612. Backwards, divide the quotient again until it reaches 0, then read the remainders from last to first: 9612 → remainder 12 (C), 600 → 8, 37 → 5, 2 → 2, so 0x258C.

In real work, let the browser console do it: (45).toString(16) gives '2d', parseInt('2D', 16) gives 45, and 0x2D typed as-is is already 45. Doing it by hand a few times is what makes a code point readable at a glance.

Start + offset

The mosaics sit in a row of code points starting at U+1FB00, like numbered seats. A seat's offset is how far it is from the first one. Because the row starts at …00, the last two hex digits of a mosaic's code point are its offset: U+1FB13 is offset 0x13, which is 19.
