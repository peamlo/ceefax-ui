# `dist` is minified, and each entry point has a brotli size budget

Nothing measured how big an entry point was, so a PR could double the stylesheet unnoticed (issue #47). The `package` job's `assert-package` gate now brotli-compresses every public entry point in the installed tarball and fails if one is over its budget in `scripts/size.mjs`. A JS entry counts the files it imports, so the `./elements` barrel carries both elements. Every file export needs a budget, so a new element subpath can't ship unmeasured. The existing "CSS exports are pure CSS" check (issue #45) keeps ADR-0001's zero-bytes-of-JS promise for `./css` and `./tokens`. A separate `size-comment` job posts the sizes and the delta against the base branch on the PR. It is the only job that can write to PRs, and it never runs PR code. Raising a budget is a one-line change, so growth shows up in review. The budgets are sized to the open roadmap, not to the measured size plus about 10% as issue #47 first proposed. About a dozen open issues add CSS to the core, at roughly 190 B brotli per component, and a tight budget would fail nearly every one of those PRs. A budget catches accidents instead, such as losing minification, a stray `@import` or a dependency pulled into an element. Every PR's comment still shows its delta.

The library build minifies `dist/index.css` and `dist/tokens.css` with esbuild after PostCSS. That cut the CSS core from 5.6 kB to 2.3 kB brotli, since the source is mostly comments. esbuild was already installed through Vite and Storybook at the same version, so it is a direct dev dependency now and adds nothing to the install. Storybook and the demo read `src/`, so they stay unminified. The commented sources still ship in `src/` for anyone reading the tokens. The elements ship as their `src/*.js` files, unminified, because consumers bundle them.

## Considered Options

- **size-limit and its PR action.** It has a dependency tree, and the action installs and builds the base branch a second time. The brotli numbers are the same as `node:zlib`'s, which needs no dependency, and the base build here reuses the job's `node_modules`.
- **cssnano in the PostCSS config.** It is a new dependency, and the shared PostCSS config would also minify Storybook's CSS.
- **No minification.** Consumers who bundle would minify anyway, but anyone linking `dist/index.css` from a CDN would download more than twice the bytes.
